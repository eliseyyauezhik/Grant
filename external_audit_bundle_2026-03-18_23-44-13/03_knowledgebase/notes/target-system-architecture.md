# Target System Architecture

## Core Idea

Система должна быть устроена как `компьютер в компьютере`: один пользовательский интерфейс для повседневной работы, один слой памяти и знаний, один агентный слой анализа и слой интеграций с внешними сервисами.

## Main Layers

### 1. My Dashboard

Это главный пользовательский интерфейс.

- Показывает проекты, inbox, важные сигналы, недавние заметки, summaries и текущие задачи.
- Должен быть удобен на десктопе и на мобильнике.
- Не обязан хранить всю сложную структуру знаний внутри себя.
- Работает как фасад над knowledge layer.

### 2. Obsidian Vault / Knowledge Base

Это долговременная память системы.

- Хранит заметки, проектные карточки, связи, summaries артефактов и структурированные сущности.
- Основной формат: `Markdown`.
- Обзор и полуструктурированные таблицы: `.base`.
- Бинарные артефакты хранятся отдельно, а в KB попадают их `md`-резюме и связи.

### 3. Agent Processing Layer

Это слой автоматической обработки.

- Читает inbox и новые материалы.
- Делает summaries для видео, картинок, аудио, документов и ссылок.
- Извлекает сущности: проекты, люди, задачи, решения, артефакты, темы.
- Создает дополнительные notes и связывает их между собой.
- Может обновлять project status, next steps, risks и weekly board.

### 4. Mobile Layer

Это не отдельная база, а отдельный режим доступа.

- Быстрый capture: заметка, голосовое, фото, ссылка, файл.
- Быстрый review: проекты, inbox, важные сигналы, задачи.
- Минимум сложной навигации.
- Мобильный доступ должен идти либо через `My Dashboard`, либо через синхронизированный Obsidian как fallback.

### 5. Integrations Layer

Это слой подключения внешних сервисов.

- Диски и файловые хранилища.
- Telegram / почта / формы / веб-клиенты.
- YouTube, документы, медиа-источники.
- Другие сервисы, которые могут писать в inbox или читать structured outputs.

## Recommended Data Model

### User-facing entities

- `Projects`
- `Inbox`
- `Artifacts`
- `Notes`
- `Tasks`
- `Areas`
- `People`
- `Decisions`

### Artifact handling

Для видео, картинки, аудио и документов не нужно пытаться хранить сам смысл внутри бинарного файла.

Нужно хранить:

- оригинальный файл или ссылку на него;
- `md`-карточку артефакта;
- summary;
- ключевые факты;
- связи с проектами и задачами;
- при необходимости extracted entities.

## Recommended User Flow

1. Пользователь заносит мысль, файл, ссылку, фото, голосовое или видео в `Inbox`.
2. Агент обрабатывает входящее и создает `md`-представление знания.
3. Знание попадает в vault и связывается с проектами, артефактами и задачами.
4. `My Dashboard` показывает уже обработанную и обзорную картину.
5. Пользователь работает в основном через dashboard, а не через внутреннюю инфраструктуру vault.

## Division Of Responsibility

### Dashboard should own

- ежедневный пользовательский UX;
- обзор проектов;
- inbox;
- быстрые действия;
- mobile access;
- агрегированные сигналы;
- entry points для запуска агентных сценариев.

### Vault should own

- долговременную память;
- заметки и summaries;
- связи между сущностями;
- structured metadata;
- project memory;
- artifact memory;
- agent-readable context.

### Agent should own

- разбор входящего;
- суммаризацию;
- классификацию;
- построение сущностей;
- поиск связей;
- предложения по структуре и следующим действиям.

## Target End State

Целевая система должна работать так:

- Пользователь живет в `My Dashboard`.
- Агент живет между dashboard и vault.
- Vault является knowledge engine и памятью.
- Mobile дает быстрый доступ к capture и review.
- Интеграции подают новые материалы в inbox и получают из системы обработанные результаты.

## Immediate Architecture Priorities

1. Сделать `My Dashboard` верхним UX-слоем, а не конкурирующей системой.
2. Перестроить текущий vault под более понятные user-facing сущности: проекты, inbox, artifacts.
3. Определить единый inbox pipeline для ручного и автоматического поступления материалов.
4. Определить формат `md`-карточек для артефактов: video, image, audio, doc, link.
5. Определить, какие agent actions запускаются автоматически, а какие по кнопке из dashboard.
