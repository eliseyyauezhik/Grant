# Мета-Системная Архитектура и Анализ Проектов

## 1. Резюме (Executive Summary)

На данный момент у вас в `ПРОЕКТЫ` развернута амбициозная экосистема локальных LLM-агентов, UI-дашбордов и баз знаний. Вы успешно переходите от разрозненных скриптов к системному управлению проектами (AI Workspace, Obsidian Vault, Гранты).
Цель — **создать хорошо организованную базу данных с возможностью анализа её сущностей с помощью ИИ-агентов** — уже частично реализуется через связку Obsidian и локальных скиллов (Skills). Ниже представлена целевая архитектура и мета-рекомендации для завершения этого перехода.

## 2. Анализ текущих сущностей

Ваши проекты (`Мой Дашборд`, `Грант для гимназии Давыдова`, `coPaw-telegram`, `ИИ-мониторинг`) имеют общие структурные бизнес-сущности:

1. **Projects (Проекты)** — высокоуровневые инициативы (`projects.json` в Дашборде).
2. **Domains / Categories** — Инфраструктура, Образование, AI/Боты, Медиа.
3. **Agents / Skills** — Исполнители (например, `youtube-monitoring`, `task-executor`).
4. **Knowledge Base (KB)** — Ваши мысли, гипотезы, сервисы и источники (Obsidian vault).
5. **Tasks (Задачи)** — Actionable items, трекаются в Kanban, `progress.md`, и `projects.json`.

На данный момент **проблема** заключается в том, что данные дублируются: статус проекта живет в `projects.json` для дашборда, в `.md` файлах Obsidian, и в локальных `task.md`.

## 3. Мета-Системная Архитектура (Target State)

Для того чтобы ИИ-агенты могли системно анализировать вашу жизнь и проекты, **Источник Истины (Single Source of Truth)** должен быть один, а интерфейсов может быть много.

### Уровень 1: Единая База Данных (Data Layer)

*Рекомендация:* Использовать **Obsidian Vault (`workspace/`)** как ядро БД.

- *Почему:* Формат Markdown (с YAML Frontmatter) идеален для чтения ИИ-агентами (RAG) и одновременно удобен для человека. Графовая структура Obsidian естественным образом описывает связи между проектами, скиллами и идеями.
- *Структура сущностей (в YAML заголовках `.md` файлов):*
  - `type: project`, `status: active`, `progress: 40`, `tags: [RAG, AI]`
- JSON из "Мой Дашборд" должен **генерироваться** из этих Markdown-файлов скриптом-агентом, а не вестись вручную.

### Уровень 2: Аналитика и Агенты (Agent Layer)

*Рекомендация:* Использовать **NotebookLM MCP** для поиска инсайтов.

- В последних логах видно, что вы настраивали интеграцию с Google NotebookLM. Вы можете загружать весь ваш `workspace/` (Obsidian) в NotebookLM.
- Это даст вашим локальным агентам (через `notebooklm-mcp` tools) возможность задавать мета-вопросы: *"Какие проекты пересекаются по стеку?", "Какой проект сейчас потребляет больше всего усилий по логам?"*
- Локальные скрипты (Antigravity Skills) выступают "рабочими руками" (изменяют файлы), а NotebookLM выступает "аналитиком" (читает файлы).

### Уровень 3: Интерфейсы (UI Layer)

*Рекомендация:* Разделение UI для разных задач.

- **Мой Дашборд (Web/PWA):** Для быстрого обзора "сверху" (чтение сгенерированного `projects.json`).
- **Obsidian:** Для глубокой работы, редактирования связей и мыслей.

## 4. Архитектоника (Пошаговый План)

1. **Конвергенция данных:** Напишите (или поручите мне) скрипт, который возьмет `projects.json` из "Мой Дашборд" и создаст под каждый проект `.md` файл в Obsidian `workspace/projects/` с нужными YAML-тегами.
2. **Архитектура папок:**
    - `AI_Workspace/KnowledgeBase/Entities/Projects`
    - `AI_Workspace/KnowledgeBase/Entities/Agents`
    - `AI_Workspace/KnowledgeBase/Entities/Ideas`
3. **MCP Integration:** Убедиться, что ваш локальный агент имеет доступ к чтению папки `KnowledgeBase`. Любой запрос на аналитику (например: *"найди все проекты связанные с образованием и выведи их прогресс"*) агент будет превращать в локальный `grep_search` или запрос к встроенному SQLite/VectorDB.
4. **Синтез знаний:** Регулярно запускать агент, который делает "сводку" по всем обновившимся проектам за неделю и кладет в папку `Reports`. Это закроет вашу потребность в "системном использовании проектов в ваших интересах".

## 5. Вывод

Ваша текущая стратегия перехода в Obsidian («Markdown-first, graph-first») абсолютно верна для эры AI-агентов. Окончательным шагом станет перенос метаданых (прогресс, таски, связи) из разрозненных JSON обратно в свойства Obsidian-файлов, откуда агент (через скрипт экспорта или RAG напрямую) сможет формировать красивые Дашборды и отвечать на глобальные мета-вопросы.
