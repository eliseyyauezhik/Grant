# КОРА 35 — Операционная система проекта

Пакет файлов для запуска агентной системы, помогающей реализовать юбилейный проект КОРА 35 и его постпроекты.

---

## Что в пакете

**Базовые документы (все агенты должны их «знать»):**

- `01_CoreContext.md` — общий контекст проекта. Грузится в системный промпт каждого агента.
- `02_Filter_KORA35.md` — одностраничный фильтр для оценки любого предложения/решения.
- `03_FourLayers.md` — архитектура из 4 слоёв (A: Событие, B: Новый ритм, C: ОС-КОРА, D: Методология).
- `04_ImplementationPlan.md` — план реализации с фазами и контрольными точками.
- `05_UserManual.md` — личная инструкция Дмитрию: как пользоваться системой, не утонуть, не выгореть.

**Агенты (системные промпты):**

- `Agent_Archivist.md` — Архивариус (хранит документы, отвечает «что у нас есть по теме X»).
- `Agent_Coach.md` — Супер-коуч (внутреннее состояние Дмитрия, осознанность, не льстит).
- `Agent_PM.md` — Проектный менеджер (сроки, бюджет, скоуп, реалистичность).
- `Agent_DevilsAdvocate.md` — Адвокат дьявола (критика, оппонирование, поиск слабых мест).
- `Agent_Orchestrator.md` — Оркестратор (опционально, для мультиагентных систем).

**Маршрутизация:**

- `Routing_Template.md` — таблица «когда какого агента звать». Для ручного режима.

## Как развернуть

### Вариант 1. Простой (рекомендую начать с него)

Один аккаунт Claude/GPT, четыре разных чата/проекта, в каждом — свой системный промпт.

1. Создаёшь 4 проекта (Claude Projects) или 4 кастомных GPT.
2. Каждому даёшь:
   - системный промпт из соответствующего `Agent_*.md`
   - PLUS прикладываешь `01_CoreContext.md`, `02_Filter_KORA35.md`, `03_FourLayers.md` как файлы знаний
3. Маршрутизацию делаешь сам по `Routing_Template.md`.

Плюсы: запускается за 30 минут. Никакого кода. Контроль полный.
Минусы: переключаться между чатами руками. Контекст в чатах накапливается.

### Вариант 2. Мультиагентный (CrewAI, LangGraph, AutoGen и т.п.)

1. Каждый `Agent_*.md` превращаешь в системный промпт агента в фреймворке.
2. `01_CoreContext.md` грузишь как shared knowledge base.
3. Активируешь `Agent_Orchestrator.md` — он маршрутизирует запросы.
4. JSON-схемы input/output под конкретный фреймворк дописываешь сам.

Плюсы: автоматическая маршрутизация. Меньше нагрузки на тебя.
Минусы: нужно программное окружение. Дольше дебажить. Чаще ошибаются.

### Вариант 3. Claude Code или агентский CLI

Запускаешь Claude Code как координатор. Каждый агент — отдельная сессия с системным промптом из файла. Базу знаний держишь в общей папке.

## Что менять, что не менять

**Менять можно/нужно:**
- Контекст по компании в `01_CoreContext.md` (по мере того, как появляется новая информация о людях, ситуации, событиях).
- План в `04_ImplementationPlan.md` (план — живой документ).
- Шаблоны маршрутизации (когда поймёшь, как реально работаешь).

**Менять НЕ стоит без серьёзных оснований:**
- Принципы в `02_Filter_KORA35.md`. Это этическое ядро проекта. Меняется только после серьёзного размышления.
- Архитектуру 4 слоёв. Перепроверь через 3 месяца после старта — но не раньше.
- Системные промпты агентов. Их функция — устойчивость. Не подстраивай их под настроение.

---

## Когда обращаться к Claude (внешний помощник)

См. подробнее в `05_UserManual.md`. Кратко:

- Когда нужно принять стратегическое решение, которое затронет 2+ слоёв системы.
- Когда чувствуешь, что система начинает противоречить сама себе.
- Когда хочешь переосмыслить часть архитектуры.
- Когда нужно сделать архитектурный снапшот.

НЕ к Claude:
- Оперативные вопросы — к локальным агентам.
- Эмоциональная разгрузка вне работы — к близким, психологу, друзьям.
- Простые справки — к Архивариусу.
