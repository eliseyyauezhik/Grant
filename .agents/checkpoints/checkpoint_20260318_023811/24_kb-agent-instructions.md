# KB Agent Instructions

Источник: `D:\ЯндексДиск\Yandex.Disk\ПРОЕКТЫ\kb_agent_instructions.docx`

## Summary

Документ описывает рекомендуемую связку Obsidian vault + агентный харнес. Главные принципы: один vault в одной директории, только Markdown внутри рабочей области, отдельные skills и templates, навигация по знаниям через граф ссылок, а не через слепое чтение файлов.

## 1. Vault Architecture

### 1.1 One Vault, One Directory

- Obsidian и агент должны работать из одной и той же папки.
- Агентный харнес нужно запускать из корня vault.
- Если запускать Obsidian и агента из разных папок, заметки и связи между ними перестают быть общим рабочим контекстом.

### 1.2 Markdown Only

- Все заметки, инструкции, шаблоны и промпты должны храниться в `.md`.
- Внутри рабочей директории агента не должно быть `.doc`, `.docx`, `.pdf` и других внешних форматов.
- Markdown выбран как общий читаемый формат для Obsidian и LLM-агентов.

### 1.3 Recommended Structure

```text
workspace/
  agents.md
  skills/
  assets/
  projects/
  notes/
```

### 1.4 Graph Navigation

- Заметки связываются через wikilinks: имя заметки помещается в двойные квадратные скобки.
- При наличии Obsidian CLI агент должен использовать `obsidian links <note>` и `obsidian backlinks <note>`, а при необходимости дополнять их `obsidian search`.
- Идея документа: сначала понять связи заметки, затем читать ее содержимое.

## 2. Agent Setup

### 2.1 `agents.md`

В корне vault должен лежать `agents.md` или `AGENTS.md`, который задает:

- роль агента;
- язык ответов;
- правила создания файлов;
- список используемых инструментов;
- ссылки на skills для типовых задач.

Пример из документа:

```md
Ты - рабочий ассистент в Obsidian vault.
- Все новые файлы создавай в формате Markdown
- После создания файла открывай его через Obsidian CLI
- При работе с канбаном используй skills/kanban-skill.md
- Отвечай на русском языке
```

### 2.2 Skills

Документ рекомендует держать отдельные Markdown-skills под разные типы задач:

- `kanban-skill.md` для карточек, колонок и подзадач;
- `writing-skill.md` для текстов и сценариев;
- `capture-skill.md` для разбора входящего текста;
- `review-skill.md` для анализа заметок и поисков связей.

### 2.3 Templates in `assets/`

- Для стабильного результата агент должен читать шаблоны перед созданием новых сущностей.
- Шаблоны особенно важны для карточек, заметок и задач.

## 3. Capture and Automation

### 3.1 Unstructured Text to Tasks

Рекомендуемый workflow:

1. Получить неструктурированный текст.
2. Разобрать его на отдельные задачи.
3. Определить исполнителя и проектный тег.
4. Создать карточки и подзадачи в Markdown.

Пример промпта из документа:

> У меня есть вот такой набор задач от коллеги: [вставить текст]. Распредели эти задачи по моему канбану согласно skills/kanban-skill.md. Используй шаблон из assets/task-template.md. Язык карточек - русский.

### 3.2 Obsidian CLI

Документ рекомендует:

- включить CLI в настройках Obsidian;
- использовать `obsidian --help` для проверки;
- открывать новые заметки через `obsidian open <note>`;
- работать со связями через `links` и `backlinks`.

### 3.3 Terminal in Obsidian

- При желании можно включить плагин `Terminal`.
- Это позволяет запускать агентный харнес прямо внутри интерфейса Obsidian.

## 4. Agent as Project OS

- Агент может быть точкой входа в рабочий процесс: создавать заметки, открывать их, раскладывать задачи по канбану и связывать материалы.
- Для task-management документ рекомендует плагин `Kanban`, где сама доска является Markdown-файлом.
- Также упоминаются субагенты, hooks и самоулучшающиеся skills.

## 5. Initial Setup Checklist

1. Создать `workspace/`.
2. Открыть папку как Obsidian vault.
3. Включить Community Plugins и установить `Terminal`, `Kanban`.
4. Включить CLI.
5. Создать `agents.md`.
6. Создать `skills/`.
7. Создать `assets/`.
8. Запускать агент из той же папки.
9. Проверить, что агент видит `agents.md`.
10. Проверить `obsidian --help`.

## Local Adaptation for This Repository

- Vault вынесен в `workspace/`, чтобы не смешивать базу знаний с остальными материалами репозитория.
- Бинарные файлы изолируются в `workspace/_assets_bin/`, а не в основном note graph.
- В текущем окружении `obsidian` CLI уже установлен и может использоваться из терминала.
- Для service-oriented database в vault разрешены `.base` файлы, так как это официальный нативный формат Obsidian для Bases.
- Community plugins хранят служебные файлы в `.obsidian/plugins/`; это часть конфигурации vault, а не основной KB-контент.
- В текущей локальной версии CLI рабочие команды навигации — `links` и `backlinks`, а не `link-path` и `backlink-path`.
