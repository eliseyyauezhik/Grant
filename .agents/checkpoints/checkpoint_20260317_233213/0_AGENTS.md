# Global Project Rules (Antigravity Agentic IDE)

Эти правила (AGENTS.md) являются единым источником истины (Single Source of Truth) для всех AI-агентов (Antigravity, Claude Code и т.д.), работающих в данном репозитории.

## 1. Оптимальный Workflow (RPI)

Агенты должны строго следовать методологии Research → Plan → Implementation:

1. **Research:** Всегда анализировать `vibe` (описание от пользователя), определять edge-cases, паттерны и угрозы безопасности. Создавать `research_notes.md`.
2. **Plan:** Формировать детальный `implementation_plan.md` (стек, структура файлов, схемы БД, endpoint-ы, тесты) и разбивать его в `task.md`. Ожидать ручного ревью пользователя (Product Owner).
3. **Implementation:** Реализовывать задачи строго по одной (focus!). Всегда использовать `artifacts` (diffs) как доказательство.
4. **Verification & Compaction:** Всегда проверять результаты (тесты, линтеры). При превышении окна контекста (~40%) генерировать `progress.md` для чистого перезапуска сессии.

## 2. Context & Code Engineering (Standards)

* **Security First:** Обязательна валидация всех входящих данных, защита от инъекций, обработка ошибок без утечки чувствительных данных (OWASP Top 10).
* **Testing:** Целевое покрытие > 80%. Любой новый функционал должен сопровождаться авто-тестами (использование тестовых фреймворков релевантных стеку).
* **Architecture:** Код должен быть модульным (SOLID, DRY). Отдавать предпочтение читаемости над хитроумными сокращениями.
* **Language & Naming:** Строгая типизация (где применимо, например, TypeScript strict mode или Python type hints). Понятный нейминг переменных и функций (что делает, а не как).
* **Tools & Skills:**
  * Максимально использовать существующие `skills` из папки `.agents/skills/`.
  * При вызове системных команд ВСЕГДА проверять логи.

## 3. Взаимодействие с пользователем (Product Owner)

* Пользователь НЕ пишет код. Он задает направление (vibe) и утверждает планы.
* Агент обязан запрашивать разрешение на `deploy`, крупные архитектурные сдвиги и `commit`, если это не согласовано заранее.
* Минимум "воды" в чате, максимум действий: выдача артефактов, запуск тестов и отображение результатов.

---
*Особые директивы:* В случае сомнений в архитектуре, используй техники Self-Consistency (пара вариантов на выбор) или Chain-of-Verification.
