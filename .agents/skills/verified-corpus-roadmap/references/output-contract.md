# Output Contract

## Required Deliverables

1. `verification ledger`
   - concise line per claim
   - primary source link
   - basket
   - implication
2. `ranked knowledge register`
   - score
   - applicability
   - impact
   - volatility
   - effort
3. `human-readable roadmap`
   - what is stable
   - what is useful but not yet fully verified
   - what should stay experimental
   - recommended sequence of changes
4. `open questions`
   - unresolved checks
   - future experiments

## Preferred Markdown Shape

Use this order:

1. status and dataset scope
2. primary sources checked
3. verified knowledge
4. probable but unverified
5. volatile or contradicted
6. ranking table
7. roadmap phases
8. next actions
9. open questions

## If Existing Artifacts Already Exist

- Reuse structured outputs instead of redoing extraction.
- Link the new roadmap back to the existing run folder.
- Keep the roadmap readable without needing to open raw JSON first.
